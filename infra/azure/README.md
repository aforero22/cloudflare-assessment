# Azure origin infrastructure

Origin VM for the Cloudflare assessment, deployed with the Azure CLI scripts in this folder.

## Resources

| Resource | Name | Details |
|---|---|---|
| Resource group | `rg-cf-assessment` | Tags `project=cf-assessment`, `owner=aforero` |
| VM | `vm-cf-origin` | Ubuntu 24.04 LTS (`Canonical:ubuntu-24_04-lts:server:latest`), user `azureuser`, SSH key only |
| Size | `Standard_D2als_v6` | 2 vCPU, 4 GiB (B-series sizes had no capacity in the region) |
| OS disk | generated by `az vm create` | 30 GB, `Standard_LRS` |
| Public IP | `pip-cf-origin` | Static, Standard SKU: **68.221.177.94** |
| Network | `vnet-cf-origin` / `snet-cf-origin` | |
| NSG | `nsg-cf-origin` | see below |

Region: **spaincentral** (`westeurope` was not accepting new resources at deployment time).
`deploy.ps1` takes an ordered list of sizes (`-VmSizes`) and falls back to the next one on capacity or quota errors.

## Network rules

NSG `nsg-cf-origin` (inbound):

| Rule | Priority | Port | Source |
|---|---|---|---|
| `allow-ssh-admin` | 100 | TCP 22 | administrator IP `/32` |
| `allow-https-cloudflare-v4` | 110 | TCP 443 | <https://www.cloudflare.com/ips-v4> |
| `allow-https-cloudflare-v6` | 120 | TCP 443 | <https://www.cloudflare.com/ips-v6> |

IPv4 and IPv6 are separate rules (Azure does not mix address families in one rule). Everything else
inbound is denied by the default rules; port 80 is closed. ufw on the VM enforces the same policy as a
second layer (`deny incoming`, 22 from the admin IP, 443 from each Cloudflare range).

## Hardening

`apt upgrade`, `unattended-upgrades`, nginx + ufw, `PasswordAuthentication no` (verified with `sshd -T`).
Application, nginx and cloudflared setup: [`../origin/provision.sh`](../origin/provision.sh).

## Deploy / redeploy

Requirements: Azure CLI already logged in (the scripts never run `az login`; set `AZURE_CONFIG_DIR`
or pass `-AzureConfigDir` to use an isolated profile) and an SSH key pair `~/.ssh/cf-assessment`.

```powershell
cd infra\azure
.\deploy.ps1            # resource group, NSG, rules and VM (idempotent)
.\deploy.ps1 -Harden    # same + harden.sh over SSH
```

Useful parameters: `-AdminIp` (defaults to the caller's public IP via <https://api.ipify.org>), `-VmSizes`,
`-Location`, `-SubscriptionId`, `-AzureConfigDir`.

## Cost (approximate, pay-as-you-go, 24/7)

VM `Standard_D2als_v6` ~60–70 USD/month, static IP ~3.6, 30 GB disk ~1.5 → **~65–75 USD/month**.
Deallocate when idle (`az vm deallocate -g rg-cf-assessment -n vm-cf-origin`).

## Teardown

```powershell
.\teardown.ps1                  # asks for confirmation (type the resource group name)
.\teardown.ps1 -Force -NoWait
```

Deletes the whole `rg-cf-assessment` group. A redeploy gets a new public IP: update `origin_ip` in
`infra/cloudflare/terraform.tfvars` and re-apply.
